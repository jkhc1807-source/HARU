# 하루여행 먹·애시드 디자인 개편 설계

작성일: 2026-09-14
복원 지점: `design-before-2026-09-14` 태그 (커밋 `1321ca9`)

## 목적

디자인을 두 가지 이유로 개편한다. 첫째, 사용자가 현재 화면을 두고 **기억에 안 남고, 지루하고, 촌스럽다**고 평가했다. 둘째, 그 아래 스타일 기반이 무너져 있다. 디자인 토큰 12개를 정의해두고 실제로는 **고유 색상 380개를 하드코딩**해 쓰고 있어, 색 하나를 바꾸려면 수십 곳을 고쳐야 한다.

두 문제는 한 작업으로 푼다. 토큰 체계를 먼저 세우고, 그 위에서 새 시각 언어를 적용한다.

## 현재 상태 실측

| 항목 | 수치 |
| --- | --- |
| 고유 hex 색상 | 380개 (사용 540회) |
| 그중 초록 계열 | **197개** (사용 275회) |
| 거의 흰색 계열 | 65개 |
| 정의된 토큰 | 12개 (사용 58회) |
| `@media(max-width:800px)` 블록 | 33개로 분산 |
| `!important` | 13개 |
| `globals.css` | 841줄 / 98KB |
| 12px 미만 글씨 | 46곳 (8·9·10·11px) |
| 44px 미만 터치 타깃 | 16개 |
| 모바일 히어로 높이 | 1223px (390px 화면 기준 1.4화면) |
| `og.png` | 2.4MB |
| `haru-forest.jpg` | 430KB |
| 파비콘 | **연결 안 됨.** `public/favicon.svg`는 Next.js 스타터 기본 아이콘이며 HTML에 링크가 없다 |

초록 197개는 의미 있는 다양성이 아니라 표류다. 같은 역할의 색을 매번 새로 찍었다.

## 방향 결정

사용자와 네 가지 방향을 시안으로 비교한 뒤 **A(먹 & 애시드)** 를 선택했다. 고대비 에디토리얼 — 종이색 배경, 먹색 텍스트와 테두리, 형광 라임 강조.

선택 근거:

- "기억에 안 남음"과 "촌스러움"에 가장 직접적으로 답한다.
- 카카오 지도가 흰색이라 **밝은 배경이 실용적으로 유리하다.** 어두운 방향(자정 & 감귤)을 택했다면 어두운 화면에 흰 지도가 뚫려 보이는 문제를 계속 다뤄야 했다.
- 형광 라임은 기존 라임(`#c8db97`)의 후손이라 브랜드가 완전히 단절되지 않는다.

A의 약점도 기록한다. **A는 차갑고 도시적이라 "지루함"이 자동으로 해결되지 않는다.** 색이 아니라 타이포 대비와 모션으로 풀어야 하며, 이 설계에 명시적으로 포함한다.

## 비목표

- 기능 로직 변경. 출발지, 즐겨찾기, 일정 생성·저장·공유, 관리자 권한, 카카오 검색, Supabase 동기화는 일절 손대지 않는다.
- Tailwind·SCSS 등 새 스타일 체계 도입. `AGENTS.md` 원칙에 따라 현재 일반 CSS를 유지한다.
- 새 npm 의존성 추가.
- 정보 구조 변경. 사용자가 "산만함"은 불만으로 꼽지 않았다. 화면 순서와 흐름은 유지한다.

## 1. 토큰 체계

`app/tokens.css`에 정의하고 `app/globals.css`가 import 한다. 파일을 여럿으로 쪼개지 않는다. 사용자가 직접 만질 파일 하나만 분리하는 것이 요점이다.

### 색 (11개)

```css
:root {
  --ink:        #14150F;  /* 제목·본문·강조 테두리 */
  --ink-soft:   #4A4B44;  /* 보조 텍스트 */
  --ink-faint:  #6D6E67;  /* 캡션·비활성 */
  --paper:      #F1F0EA;  /* 페이지 배경 */
  --surface:    #FFFFFF;  /* 카드 */
  --line:       #D9D8D0;  /* 기본 테두리 */
  --line-bold:  #14150F;  /* 카드 테두리 */
  --acid:       #D6FF3D;  /* 강조 (면으로만) */
  --acid-deep:  #B4DC1E;  /* 호버·누름 */
  --danger:     #C43B22;  /* 오류 */
  --ok:         #2D7B4D;  /* 성공 */
}
```

의미로 이름 붙인다. `--green-3` 같은 이름은 색을 바꾸는 순간 거짓말이 된다.

### 색 대비 검증 결과

`--paper` 위에서 측정한 실제 대비다. 모든 텍스트 조합이 WCAG AA(4.5:1)를 통과한다.

| 조합 | 대비 | 판정 |
| --- | --- | --- |
| `--ink` / `--paper` | 16.08 | 통과 |
| `--ink` / `--surface` | 18.36 | 통과 |
| `--ink-soft` / `--paper` | 7.72 | 통과 |
| `--ink-faint` / `--paper` | 4.51 | 통과 |
| `--acid` / `--ink` (버튼) | 15.94 | 통과 |
| `--ink` / `--acid` (하이라이트) | 15.94 | 통과 |
| `--danger` / `--paper` | 4.60 | 통과 |
| `--ok` / `--paper` | 4.54 | 통과 |
| `--acid` / `--surface` | **1.15** | **금지** |
| `--acid-deep` / `--surface` | **1.59** | **금지** |

`--ink-faint`와 `--ok`는 초안값(`#7C7D75`, `#2E7D4F`)이 각각 3.64, 4.42로 기준에 못 미쳐 위 값으로 조정했다.

**형광 라임을 밝은 배경 위 글자색으로 쓰는 것을 금지한다.** 대비 1.15는 사실상 보이지 않는다. 라임은 배경(면)으로 깔고 그 위에 먹 글씨를 얹는 방식만 허용한다.

### 타이포 (6단)

```css
:root {
  --t-hero:  clamp(42px, 9vw, 68px);
  --t-h2:    clamp(24px, 4vw, 34px);
  --t-h3:    17px;
  --t-body:  14px;
  --t-small: 13px;
  --t-micro: 12px;  /* 최소. 이보다 작은 글씨 금지 */
}
```

**12px을 절대 하한으로 둔다.** 현재 8·9·10·11px 글씨가 46곳이며, 이것이 "촌스러워 보임"의 주요 원인이다. 작은 글씨는 정보를 담는 대신 자신 없어 보이게 만든다.

### 간격 (6단)

```css
:root {
  --s1: 4px;  --s2: 8px;  --s3: 12px;
  --s4: 20px; --s5: 32px; --s6: 56px;
}
```

### 형태

```css
:root {
  --bd:             1.5px solid var(--line);
  --bd-bold:        2px solid var(--line-bold);
  --shadow-hard:    6px 6px 0 var(--ink);
  --radius:         0;    /* 카드·패널·입력 */
  --radius-control: 4px;  /* 버튼·칩 */
  --tap:            44px; /* 터치 타깃 최소 높이 */
}
```

카드는 각지게, 버튼과 칩만 살짝 둥글게 둔다. 전부 각지면 딱딱해 보인다는 판단이다.

**총 29개 토큰** — 색 11, 타이포 6, 간격 6, 형태 6. 하드코딩된 380개 색이 색 토큰 11개로 수렴하며, 이후 색 변경은 11줄 수정으로 끝난다.

## 2. 시각 언어

### 컴포넌트 규칙

| 요소 | 규칙 |
| --- | --- |
| 카드·패널 | `--surface` 배경 + `--bd-bold` + `--shadow-hard` |
| 기본 버튼 | `--ink` 배경 + `--acid` 글씨 |
| 보조 버튼 | `--surface` 배경 + `--bd-bold` |
| 칩(취향) | 테두리만 → 선택 시 `--ink` 채움 + `--acid` 글씨 |
| 방문 번호 | 배지 없이 큰 숫자 노출 (36px) |
| 섹션 구분 | 배경색이 아니라 `--bd-bold` 가로선 |
| 강조 | `--acid`는 면으로만 |

### 지루함 해결 1 — 크기 대비

현재 글씨 크기가 고르게 작다. A의 힘은 비율에서 나온다.

| 쌍 | 비율 |
| --- | --- |
| 헤드라인 68px ↔ 아이브로우 12px | 5.7배 |
| 방문 번호 36px ↔ 시간 메타 12px | 3배 |
| 소요시간 34px ↔ 장소 수 12px | 2.8배 |

여행 계획에서 숫자가 주인공인데 현재는 모두 작다. 숫자를 크게 노출한다.

### 지루함 해결 2 — 물리적 모션

A에 맞는 모션은 부드러운 것이 아니라 끊어지는 것이다. 세 가지만 추가한다.

1. **하드 섀도 눌림** — 버튼·카드를 누르면 `2px` 밀리며 그림자가 접힌다. CSS 두 줄.
2. **라임 와이프** — 일정 생성 완료 시 헤드라인 하이라이트가 왼쪽에서 쓸려 들어온다.
3. **숫자 카운트업** — 소요시간·장소 수가 0에서 올라간다.

기존 워커 애니메이션은 유지한다. 단 **주황(`#FF6A2B`)은 A 팔레트에 없으므로 폐기하고, 워커와 경로선을 `--ink`로 바꾼다.** 흰 지도 위 대비도 이쪽이 낫다. 형광 라임은 흰 지도에서 보이지 않으므로 경로선에 쓸 수 없다.

`prefers-reduced-motion: reduce`는 현행대로 존중한다. 위 세 모션 모두 해당 설정에서 비활성화한다.

### 지도

지도만 흰색이라 `--paper` 배경과 미세하게 어긋난다. `--bd-bold`로 감싸 의도된 액자로 만든다.

## 3. 모바일 구조

| 항목 | 현재 | 목표 |
| --- | --- | --- |
| 히어로 높이 (390px 화면) | 1223px (1.4화면) | 약 440px (0.5화면) |
| 전체 문서 | 4.3화면 | 약 3화면 |
| 44px 미만 터치 타깃 | 16개 | 0 |
| 12px 미만 글씨 | 46곳 | 0 |
| 지도 높이 | 390px | 480px |

가장 큰 문제는 히어로다. 계획 입력창에 닿기까지 1.4화면을 스크롤해야 하며, 첫 화면 전체가 숲 사진이다.

**터치 타깃** — 버튼·칩·입력·`summary`에 `min-height: var(--tap)`을 적용한다. 현재 40px, 41px, 34px이 섞여 있다.

**반응형 정리** — 흩어진 33개의 `@media(max-width:800px)` 블록을 컴포넌트별로 묶는다. 현재는 모바일에서 무엇이 바뀌는지 파악하려면 파일 전체를 뒤져야 한다. 분기점 값 자체(800px)는 바꾸지 않는다.

**`!important` 13개** — 토큰화 과정에서 명시도로 해결 가능한 것은 제거한다. 남길 것은 사유를 주석으로 남긴다.

## 4. 브랜드 자산

### 히어로 그래픽 (사진 폐기)

숲 사진은 A와 언어가 다르다. 서정적인 사진과 고대비 타이포는 함께 두면 서로를 약화시킨다. 사용자와 협의해 **사진 없이 그래픽**으로 결정했다.

장식 도형이 아니라 **이 앱이 만드는 결과물 자체**를 그린다. 번호 붙은 지점이 점선으로 이어진 동선이다.

```
   ①╌╌╌╌╌②
          ╎
    ④╌╌╌╌╌③
```

`--ink` 점선, `--acid` 노드, 큰 번호. 로고의 동선 모티프와 같은 언어이며, 숲 사진과 달리 **앱의 기능을 즉시 전달한다.** 인라인 SVG로 그리므로 용량은 수 KB다.

`public/haru-forest.jpg`(430KB)를 삭제하고 Unsplash 출처 표기도 함께 제거한다.

### 로고

CSS로 계속 그린다(`.brand-mark`의 `:before`/`:after`). 이미지보다 가볍고 색 변경이 쉽다.

- 주황 해(`#e8a33f`) → `--acid` 원
- 초록 점선 동선(`#7a9e21`) → `--ink` 실선
- 워드마크는 더 굵게, 자간을 더 좁게. `여행`에 `--acid` 하이라이트를 깔아 헤드라인 언어와 통일한다.

A 팔레트에 주황이 없으므로 폐기한다.

### 파비콘 (신규)

현재 파비콘은 **연결되어 있지 않다.** `public/favicon.svg`는 파란 사각형 4개짜리 Next.js 스타터 기본 아이콘이고, `layout.tsx`에 `icons` 필드가 없으며 `app/icon.*`도 없어 HTML에 링크가 들어가지 않는다. `/favicon.ico`는 404다.

`app/icon.svg`로 배치해 Next.js가 자동으로 링크하게 한다. 디자인은 `--ink` 배경에 `--acid` 심볼 하나. 16px에서 읽혀야 하므로 워드마크는 넣지 않는다. `public/favicon.svg`는 삭제한다.

### OG 미리보기 이미지

`og.png` 2.4MB는 카카오톡·슬랙 미리보기 한도를 넘길 수 있다.

사진 대신 타이포로 만든다. A의 언어이기도 하고, 실용적 이유가 더 크다 — 미리보기는 작게 표시되므로 사진은 뭉개지고 큰 글씨는 읽힌다.

`1200×630`, `--ink` 배경, `--acid` 하이라이트, `하루여행` + `하루가 가벼워지는 여행 플래너`. SVG로 만들어 PNG로 내보내며 **200KB 이하**를 목표로 한다.

### 취향 아이콘 5개

현재 선 아이콘의 `stroke-width: 1.5`는 A의 굵은 대비에 비해 얇다. **`2.5`로 굵힌다.** 형태(`categoryIconPaths`)는 그대로 둔다.

### 삭제 대상

`public/file.svg`, `public/globe.svg`, `public/window.svg` — Next.js 스타터 잔재, 참조 0곳.

## 6. 2단계 진행과 검증 게이트

### 1단계 — 토큰화 (역할 배정 검증)

하드코딩된 380개 색을 색 토큰 11개로 치환한다. 토큰에는 **각 역할에서 가장 많이 쓰인 색값**을 넣는다. 색 계열은 유지한다 — 초록은 아직 초록이다.

여기서 분명히 해둘 것이 있다. **화면이 완전히 동일할 수는 없다.** 197개 초록을 4개로 합치면 픽셀은 반드시 달라진다. 1단계의 목적은 화면 보존이 아니라 **역할 배정이 옳은지 검증하는 것**이다. 텍스트 색이 테두리 색으로 잘못 들어가는 것 같은 실수를 잡는 단계다.

> **게이트:** 320·390·768·1440px 네 폭에서 전후 스크린샷을 픽셀 비교하고, 차이를 두 종류로 나눈다.
>
> - **허용:** 색만 미세하게 달라진 경우. 판정 기준은 채널당 차이 24 이하(255 기준 약 9%). 같은 역할의 인접한 색을 합친 결과다.
> - **불합격:** 레이아웃이 밀리거나, 밝은 면이 어두워지거나(그 반대), 텍스트와 배경이 뒤바뀌는 등 **구조적 변화.** 역할 배정이 틀렸다는 뜻이므로 고치고 다시 검증한다.

불합격 유형은 픽셀 비교에서 크고 명확하게 드러난다. 눈으로 "비슷한데?" 하고 넘기지 않고 기계가 판정한다는 점이 핵심이다.

2단계에서 이 값들은 어차피 A 팔레트로 교체된다. 따라서 1단계에서 중요한 것은 **색값의 정확성이 아니라 역할 배정의 정확성**이다.

어느 역할 토큰에도 흡수되지 않는 색이 남으면, 사유를 기록하고 2단계에서 처리한다.

### 2단계 — A 적용

토큰 값 11개를 A 팔레트로 교체하고, 컴포넌트 형태·타이포·모션·브랜드 자산을 바꾼다. 화면은 당연히 바뀌므로 픽셀 비교는 쓰지 않고 아래 기준으로 검증한다.

| 항목 | 기준 |
| --- | --- |
| 기존 자동 테스트 | 19개 통과 유지 |
| `npx tsc --noEmit` | 오류 0 |
| `npx next build` | 통과 (Vercel 배포 경로) |
| 가로 넘침 | 320·390·768·1440px에서 0 |
| 색 대비 | 모든 글자/배경 쌍 WCAG AA 4.5:1 |
| 터치 타깃 | 44px 미만 0개 |
| 글씨 크기 | 12px 미만 0개 |
| `prefers-reduced-motion` | 세 모션 모두 비활성화 확인 |
| 파비콘 | HTML에 `<link rel="icon">` 존재, 200 응답 |
| `og.png` | 200KB 이하 |

`rendered-html.test.mjs`가 현재 마크업의 특정 클래스·문구를 검증하고 있으므로, 마크업이 바뀌면 이 테스트도 함께 갱신한다. 테스트를 지우지 않고 새 구조에 맞게 고친다.
