# 하루여행 출발지·계정·교통·관리자 설계

작성일: 2026-09-01

## 목적

현재 일정의 첫 방문 장소를 실제 출발지처럼 취급하는 문제를 바로잡는다. 사용자는 실제 출발지를 선택한 뒤 별도의 여행 지역에서 하루 일정을 만들고, 출발지에서 첫 방문 장소까지의 대중교통 요약을 확인할 수 있어야 한다. 구글 로그인 사용자는 즐겨찾기와 저장 일정을 여러 기기에서 동기화하며, 관리자는 개인정보 원문을 열람하지 않고 서비스 상태를 관리한다.

## 핵심 원칙

- 실제 출발지, 여행 지역, 일정의 첫 방문 장소를 서로 다른 데이터로 관리한다.
- 비로그인 상태에서도 기존 일정 생성 기능을 계속 사용할 수 있다.
- 유료 사용 설정을 요구하지 않으며 교통 경로는 사용자가 요청할 때만 조회한다.
- 사용자별 데이터는 Supabase RLS로 분리한다.
- 관리자는 집·회사 주소와 개인 일정 내용을 열람하지 않는다.
- API 키와 관리자 권한은 브라우저 코드에 하드코딩하지 않는다.

## 사용자 흐름

1. 사용자는 다음 방법 중 하나로 실제 출발지를 선택한다.
   - 현재 위치
   - 주소·건물·지하철역 검색
   - 집·회사·기타 즐겨찾기
2. 사용자는 별도로 여행 지역, 시작·종료 시간과 취향을 선택한다.
3. 앱은 기존 방식으로 여행 지역의 하루 일정을 만든다.
4. 일정의 첫 번째 방문 장소가 교통편 목적지가 된다.
5. 사용자가 `교통편 확인`을 누르면 출발지에서 첫 장소까지의 대중교통 경로를 한 번 조회한다.
6. 앱은 총 소요시간, 예상 요금, 환승 횟수와 주요 노선을 요약하고 카카오맵 상세 길찾기 링크를 제공한다.
7. 출발지나 첫 장소가 바뀌면 기존 교통 결과를 폐기하고 다시 조회하도록 안내한다.

## 화면 설계

### 계획 카드

입력 순서는 다음과 같다.

1. `어디서 출발하나요?`
   - 출발지 검색
   - `내 위치` 버튼
   - 집·회사 등 즐겨찾기 버튼
   - 비로그인 사용자에게는 로그인 시 동기화할 수 있다는 짧은 안내
2. `어디에서 하루를 보낼까요?`
   - 기존 지역·지하철역 검색
   - 시간 범위
   - 취향 선택
3. `나만의 하루 만들기`

모바일에서는 출발지 검색과 현재 위치 버튼을 세로로 배치할 수 있게 하고, 즐겨찾기 버튼은 가로 스크롤 대신 줄바꿈한다. 320px 화면에서도 가로 넘침이 없어야 한다.

### 교통 카드

일정 목록 위에 다음 내용을 표시한다.

- 출발지와 첫 장소
- 총 소요시간
- 예상 요금
- 환승 횟수
- 주요 버스·지하철 노선
- `교통편 확인`
- `카카오맵에서 자세히 보기`

교통편은 자동 조회하지 않는다. 조회 전, 조회 중, 성공, 결과 없음, 설정 누락과 쿼터 초과 상태를 구분해 안내한다.

### 로그인

- 구글 로그인 한 가지만 제공한다.
- 비로그인 사용자는 일정 생성, 출발지 검색과 현재 위치를 사용할 수 있다.
- 로그인 사용자는 즐겨찾기와 저장 일정을 Supabase에 동기화한다.
- 첫 로그인 시 기존 브라우저 저장 데이터를 계정에 옮길지 확인한다.
- 구글의 기본 프로필 외 Drive·Calendar 등의 추가 권한은 요청하지 않는다.

### 관리자

- `/admin`은 관리자만 접근한다.
- 가입자 수, 최근 가입 현황, 저장 일정 수, 즐겨찾기 수와 API 오류 현황을 보여준다.
- 관리자는 계정을 활성화하거나 차단하고 추천 지역·공지 콘텐츠를 관리할 수 있다.
- 사용자 집·회사 주소와 개인 일정 원문은 표시하지 않는다.
- 계정 상태 변경 등 관리자 작업은 감사 기록으로 남긴다.

## 데이터 모델

### profiles

- `id`: Supabase Auth 사용자 ID
- `email`: 계정 식별용 이메일
- `display_name`: 표시 이름
- `role`: `user` 또는 `admin`
- `is_blocked`: 계정 차단 상태
- `created_at`, `updated_at`

일반 사용자는 자신의 표시 이름만 변경할 수 있다. `role`과 `is_blocked`는 관리자 서버 작업으로만 변경한다.

### favorite_origins

- `id`
- `user_id`
- `label`: 집, 회사 또는 사용자 지정 이름
- `place_name`
- `address`
- `x`, `y`
- `created_at`, `updated_at`

### saved_trips

- `id`
- `user_id`
- `name`
- `city`
- `start_time`, `end_time`
- `preferences`
- `origin`
- `plan`
- `created_at`, `updated_at`

현재 앱의 일정 구조는 불필요하게 정규화하지 않고 JSON 형태로 저장한다.

### admin_audit_logs

- `id`
- `admin_user_id`
- `action`
- `target_user_id`
- `created_at`

주소나 일정 본문은 감사 기록에 넣지 않는다.

## 인증과 권한

- Supabase Google OAuth와 PKCE 흐름을 사용한다.
- 운영과 로컬 로그인 복귀 주소만 허용 목록에 등록한다.
- Supabase publishable key만 브라우저에서 사용한다.
- `service_role` 키와 카카오 REST API 키는 Vercel 서버 환경변수에만 둔다.
- 개인 테이블은 RLS를 활성화하고 `auth.uid() = user_id`인 행만 사용자가 조회·작성·수정·삭제할 수 있게 한다.
- 관리자 페이지와 관리자 API는 서버에서 관리자 역할과 차단 상태를 확인한다.
- 일반 사용자가 자신의 `role`이나 `is_blocked`를 변경하는 경로는 제공하지 않는다.
- 최초 관리자는 구글 로그인 후 Supabase 관리 화면에서 한 번만 `admin` 역할로 지정한다.

## 교통 데이터 흐름

1. 브라우저는 선택된 출발지와 일정 첫 장소의 좌표를 서버 API로 보낸다.
2. 서버는 좌표 형식과 한국 범위를 검증한다.
3. 서버는 카카오 REST 대중교통 경로 API를 호출한다.
4. 서버는 최적 경로 한 건의 요약과 카카오맵 `landingURL`만 브라우저에 반환한다.
5. 브라우저는 결과를 현재 출발지·첫 장소 조합에만 보관한다.

요청은 `교통편 확인`을 누를 때만 발생한다. 유료 사용을 활성화하지 않으며 무료 쿼터를 사용할 수 없으면 일정 기능을 막지 않고 안내를 표시한다.

## 오류 처리

- 위치 권한 거부: 검색 또는 즐겨찾기 사용을 안내한다.
- 출발지 검색 결과 없음: 다른 주소·건물·역 이름 입력을 안내한다.
- 로그인 실패: 비로그인 기능을 계속 제공한다.
- Supabase 저장 실패: 로컬 데이터를 유지하고 재시도 안내를 제공한다.
- 교통 결과 없음: 카카오맵에서 직접 확인할 수 있는 대안을 제공한다.
- 카카오 설정 누락 또는 쿼터 초과: 원인을 구분하되 키나 내부 오류를 노출하지 않는다.
- 출발지 또는 첫 장소 변경: 이전 교통 결과를 즉시 제거한다.
- 차단 계정: 서버 데이터 접근을 거부하고 로그아웃을 유도한다.

## 구현 단계

### 1단계: 인증과 저장

- Supabase 프로젝트 연결
- 구글 로그인·로그아웃
- profiles, favorite_origins, saved_trips와 RLS
- 기존 로컬 데이터의 선택적 계정 이전

### 2단계: 실제 출발지

- 출발지 검색
- 현재 위치 선택
- 즐겨찾기 추가·수정·삭제
- 여행 지역과 출발지 상태 분리

### 3단계: 교통 안내

- Vercel 서버 API
- 카카오 대중교통 경로 조회
- 요약 카드와 카카오맵 상세 링크
- 상태 변경과 오류 처리

### 4단계: 관리자

- 서버 권한 검사
- 개인정보를 제외한 집계 통계
- 계정 활성화·차단
- 추천 지역·공지 관리
- 관리자 감사 기록

## 검증 기준

- 비로그인 상태에서 기존 핵심 일정 흐름이 유지된다.
- 구글 로그인, 로그아웃과 세션 복원이 동작한다.
- 서로 다른 두 사용자가 상대방의 즐겨찾기와 일정을 조회·변경할 수 없다.
- 일반 사용자가 관리자 화면과 API에 접근할 수 없다.
- 일반 사용자가 자신의 역할이나 차단 상태를 바꿀 수 없다.
- 위치 권한 허용·거부와 출발지 검색 실패를 재현한다.
- 출발지 또는 첫 장소 변경 시 이전 교통 결과가 사라진다.
- 교통 조회 성공, 결과 없음, 설정 누락과 쿼터 초과를 구분한다.
- 관리자 화면에 개인 주소와 일정 원문이 나타나지 않는다.
- 320px, 375px, 태블릿과 데스크톱에서 가로 넘침과 터치 동작을 확인한다.
- 테스트, 타입 검사와 프로덕션 빌드 후 Vercel에서 실제 OAuth 복귀 주소와 사용자 데이터 분리를 확인한다.

## 비목표

- 구글 Drive·Calendar 접근
- 자체 비밀번호 인증
- 앱 안에서 모든 환승 단계를 카카오맵 수준으로 재현
- 무료 쿼터를 넘는 유료 자동 결제
- 관리자의 개인 주소·일정 원문 열람
